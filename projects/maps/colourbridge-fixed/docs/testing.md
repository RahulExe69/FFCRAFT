# Testing guide — ColourBridge HUD/timer patch

## Import and save

1. Keep `projects/templates/Map1/` unchanged.
2. From the repository root run `python projects/maps/colourbridge-fixed/build_fixed_export.py`, or use the supplied working export ZIP.
3. Import/open that separate copy in Craftland Mobile using the same workflow used for the original project.
4. Save/re-export through the editor before testing. This matters because `UserLevelData_1.bytes` and `ProjectData_slot_1.meta` are not regenerated by the current source-graph builder.

## Manual cases

| ID | Steps | Expected result |
|---|---|---|
| HUD-01 | Join and wait for the welcome dialogue/intro | Creator-authored dialogue remains; the yellow `FIND THE COLOUR` banner appears once. |
| HUD-02 | Observe first target and the next two loops | No dim duplicate title is layered beneath the banner. |
| TIMER-01 | Watch the timer at the first gameplay loop | Timer starts near 11 seconds and visibly counts down. |
| TIMER-02 | Observe at least three loop transitions | Timer reaches/approaches zero and resets for the next colour cycle. |
| TIMER-03 | Observe the top-center HUD over several loops | No old countdown widgets accumulate. |
| REG-01 | Confirm tile cycling and target colour match | Existing tile cycle and `ColorHUD` colour update still work. |

Record the Craftland version, whether import/save worked, a screenshot of the first gameplay round, and a screenshot after three loops. If import fails or the timer remains stuck, stop and report the result; do not modify the golden template or further hand-edit opaque data until the runtime generation path is understood.
